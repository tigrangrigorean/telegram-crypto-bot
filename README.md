# BingX Telegram Crypto Bot

Асинхронный сканер публичного рынка USDT perpetual BingX. Одно приложение ведёт историю сигналов, общий виртуальный портфель и Telegram-подписки. Контракты, свечи и котировки поступают с биржи. Для работы нужны Docker Compose и токен бота из @BotFather.

## Запуск

```sh
cp .env.example .env
```

Откройте `.env` и укажите значение `TELEGRAM_BOT_TOKEN`. Храните файл локально. Затем выполните:

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 bot
```

Откройте бота в Telegram и отправьте `/start`. PostgreSQL создаёт внутреннюю базу, Compose генерирует пароль в отдельном томе, Alembic применяет миграции перед запуском polling. Порт базы доступен внутри сети Compose. Сохраняйте оба тома при обновлениях. Проект рассчитан на один экземпляр приложения.

## Команды

| Команда | Результат |
|---|---|
| /start, /stop | Включить или выключить доставку в текущий чат |
| /help, /status | Список команд и состояние фоновых задач |
| /coins, /top | Количество активных контрактов и кандидаты текущего сканирования |

| /stats | Число сигналов по состояниям и доля TP среди завершённых |
| /paper | Общий реализованный баланс USDT, PnL, число позиций и доля прибыльных сделок |
| /backtest | Последний сохранённый исторический прогон |

## Сканер и сигналы

Discovery обновляет контракты каждые 30 минут. Общий тикер охватывает все активные инструменты. Рейтинг учитывает изменение цены, диапазон и оборот за 24 часа, рост оборота относительно скользящей базы и спред между лучшими ценами покупки и продажи. Влияние экстремальных движений ограничено. Узкий спред и высокий оборот повышают приоритет. Сканер непрерывно перебирает все активные контракты партиями до 16. До восьми мест в партии получают кандидаты из текущего топ-48; остальные места отдаются контрактам, которые дольше всего ждали проверки. За одну пятиминутку один контракт планируется не более одного раза. Сначала проверяются закрытые свечи 5m. Сканер проверяет до восьми контрактов параллельно. Если пробой на 5m проходит фильтры объёма, волатильности, RSI и направления, бот запрашивает 15m. Часовые свечи нужны только при подтверждении на 15m. Продолжительность полного обхода зависит от размера рынка и задержек API. Счётчик попыток за текущую пятиминутку доступен в /status. Общий REST-клиент запускает до пяти запросов в секунду по умолчанию. Ответ HTTP 429 ставит запросы на общую паузу.

Для LONG требуется закрытие выше предыдущего локального максимума, для SHORT — ниже минимума. На трёх интервалах EMA 9/21/50 и гистограмма MACD должны согласоваться. RSI, ATR и относительный объём проверяются на 5m. Уровни рассчитываются по предшествующему диапазону. Вход находится на один шаг цены за экстремумом пробойной свечи, SL за пробитым уровнем с буфером ATR. TP1 и TP2 проецируют одну и полторы ширины диапазона. R/R при создании сигнала и подтверждении входа учитывает настроенные комиссии и проскальзывание на обеих сторонах сделки. Если чистый R/R до TP1 ниже порога, сигнал пропускается. Перед автоматической публикацией бот также проверяет свежесть тикера и спред. Максимальный спред по умолчанию составляет 0,25%. Команда /analyze показывает технический сетап. В бэктесте используются свечи, поэтому исторический спред в нём недоступен. Score измеряет силу объёма и пробоя после выполнения обязательных условий.

WATCH и WAITING сохраняются в одной транзакции. Уведомление WAITING содержит условие будущего входа. Следующая свежая цена подтверждает вход, только если сохраняется минимальный R/R. Пробой SL до входа или слишком далёкая цена отменяют идею. Ожидание истекает по таймеру. TP1 закрывает всю позицию, TP2 служит справочной целью.

WebSocket подписывается на инструменты с активными сигналами, максимум 20 подписок. Остальные цены поступают через общий REST-тикер. Очередь ограничена 2048 тиками. Во время разрывов или переполнения возможны пропущенные касания уровней между наблюдениями. В БД сохраняются события. Уникальные ключи защищают сигнал, переход и доставку получателю от повторной постановки. Если Telegram принял сообщение прямо перед аварией процесса, повтор при восстановлении возможен.

## Виртуальная торговля

Начальный баланс 50 USDT, риск 1% реализованного баланса, плечо 3× (максимум 5×). Маржа и резерв комиссии учитываются по всем открытым позициям. После дневного реализованного убытка 3% от баланса на начало UTC-дня новые позиции пропускаются. Вход округляет количество вниз и проверяет минимумы контракта. Комиссия и направленное проскальзывание относятся к обеим сторонам сделки. При моделировании изолированной позиции убыток ограничен выделенной маржой. Funding, ликвидация по mark price, глубина стакана и частичные исполнения не моделируются. Портфель и активные сигналы восстанавливаются из PostgreSQL.

## Историческое тестирование

```sh
docker compose exec bot python -m bot.backtest --symbol BTC-USDT --days 7 --side LONG
```

Для воспроизводимого периода добавьте `--end 2026-11-20T00:00:00Z`. Возможные направления — LONG, SHORT, both. CLI загружает историю страницами, проверяет покрытие и прогревает индикаторы. Решение принимает та же функция стратегии с доступом только к закрытым на момент решения свечам. Вход возможен со следующей свечи. При касании SL и TP в одной свече приоритет у SL. Ценовой разрыв через SL учитывается по цене открытия. В конце периода открытая сделка закрывается по последней цене. В исторической модели размер позиции непрерывный, один инструмент за прогон, без портфельного дневного лимита. Результат и сделки записываются одной транзакцией. Win rate и просадка в историческом отчёте выражены долями. Profit factor равен null при отсутствии убыточных сделок.

## Настройки

В `.env` можно переопределять параметры из `bot/config.py` в верхнем регистре. Основные значения по умолчанию:

| Параметр | Значение | Назначение |
|---|---:|---|
| SCAN_SECONDS / CANDIDATES | 1 / 48 | Пауза между партиями в секундах и число приоритетных кандидатов |
| REST_REQUESTS_PER_SECOND / MAX_SPREAD_BPS | 5 / 25 | Общий лимит REST и максимальный спред в базисных пунктах |
| BREAKOUT_MIN_ATR / BREAKOUT_CLOSE_FRACTION | 0 / 0 | Опциональные фильтры силы пробоя. При ненулевом значении задают минимальный выход за уровень в ATR и положение закрытия в диапазоне свечи по направлению пробоя |
| WINDOW / VOLUME_RATIO | 20 / 1.4 | Окно уровней и минимальный относительный объём |
| RSI_LOW / RSI_HIGH | 50 / 78 | Диапазон силы RSI, для SHORT используется 100 − RSI |
| ATR_MIN / ATR_MAX / STOP_ATR | 0.001 / 0.05 / 0.6 | Границы ATR/цена и буфер SL |
| MIN_RR / QUOTE_AGE | 2 / 30 | Минимальный R/R и свежесть тика в секундах |
| COOLDOWN / EXPIRY | 1800 / 900 | Ограничение повторов и срок ожидания в секундах |
| FEE / SLIP | 0.0005 / 0.0003 | Комиссия и проскальзывание на сторону |
| BALANCE / RISK / LEVERAGE / DAILY_LOSS | 50 / 0.01 / 3 / 0.03 | Параметры виртуального счёта |

Изменение BALANCE влияет на новый счёт. Действующий баланс хранится в БД.

## Разработка и проверка

Python 3.12+, `pip install -r requirements-dev.txt`, затем `python -m pytest -q`. Интеграционные тесты включаются через `TEST_POSTGRES=1`; используйте отдельную тестовую базу с заданным `DATABASE_URL` и предварительно выполните `alembic upgrade head`. Проверка запуска создаёт аккаунт и использует тестовые рыночные данные. Для проверки синтаксиса выполните `python -m compileall -q bot migrations tests`.
